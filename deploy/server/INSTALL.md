# OBS — Эфир на Linux x64

Пульт запускается на Linux через Docker Compose. OBS Studio может работать на том же компьютере или на другом ПК. Для Windows с OBS в базовом облачном режиме достаточно встроенного клиента OpenSSH. На сервере клонируй основной репозиторий, перейди в него и выполни `sudo bash install.sh cloud`. При необходимости на Debian/Ubuntu скрипт попробует установить Docker и Compose через apt.

Облачная авторизация состоит из логина и пароля сайта (Caddy Basic Auth поверх HTTPS) и отдельного кода пульта. Пароль OBS WebSocket используется сервером для подключения через SSH-туннель; он хранится в `.env` в кодировке Base64, которая не является шифрованием. Ограничь доступ к файлу и серверу. При повторном запуске существующий `.env` сохраняется; код можно найти в нём как `OBS_REMOTE_PAIR_CODE`.

## Облачный сервер

1. Направь DNS поддомена на VPS. Для HTTPS открой TCP 80 и 443, для туннеля оставь доступ по SSH. Порты 8787, 14455 и 4455 для интернета не открывай.
2. В OBS открой «Инструменты → Настройки сервера WebSocket», включи сервер и аутентификацию. На VPS выполни `git clone https://github.com/evi1argument/obs-efir.git`, затем `cd obs-efir` и `sudo bash install.sh cloud`. Скрипт спросит домен, данные входа и пароль OBS WebSocket. Код пульта появится на экране и сохранится в `deploy/server/.env` как `OBS_REMOTE_PAIR_CODE`.
3. На ПК с OBS запусти одну команду в PowerShell. Замени имя SSH-пользователя и адрес VPS. Порт OBS по умолчанию 4455. По первому запросу сравни отпечаток SSH-ключа VPS.

   ```powershell
   ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3 -R 127.0.0.1:14455:127.0.0.1:4455 obs-tunnel@vps.example.com
   ```

   Оставь SSH открытым во время работы пульта. Если порт OBS изменён, замени `4455` в команде.
4. Открой HTTPS-адрес на телефоне, введи логин и пароль сайта, затем код пульта.

Для отдельного SSH-аккаунта с ключом можно ограничить обратный порт. Добавь в конец `sshd_config`, выполни `sshd -t` и перечитай конфигурацию SSH:

```text
Match User obs-tunnel
    AllowTcpForwarding remote
    GatewayPorts no
    PermitListen 127.0.0.1:14455
    PermitTTY no
    MaxSessions 0
```

Если OBS запущен на самом VPS, вместо туннеля укажи порт OBS в `.env` и повтори команду установки. Захват окон Windows и системный Spotify зависят от ОС компьютера, где идёт эфир.

## Локальный Linux-сервер

Запусти команду установки выше и выбери локальный режим, затем открой `http://127.0.0.1:8787`. Публичный домен и Caddy для этого режима не нужны. Для OBS на той же машине подставь его порт в `OBS_REMOTE_WS_PORT` в `~/obs-remote/deploy/server/.env` и повтори установку. Для OBS на другом компьютере используй обратный SSH-туннель.

## Возможности

В базовом режиме сервер управляет сценами, источниками, положением слоёв, текстом и звуком в OBS. Предпросмотр показывает снимки OBS. Загрузка новых файлов на Windows, управление проигрывателем Spotify и видео до 60 кадр/с используют рабочую сессию Windows. При наличии локальной установки пульта см. [расширенный режим](./WINDOWS-INTEGRATIONS.md).

Проверка облачной установки из `~/obs-remote/deploy/server`: `docker compose -f compose.yaml -f compose.cloud.yaml -f compose.source.yaml ps`. Для локальной используй `docker compose -f compose.yaml -f compose.source.yaml ps`. Если сайт открывается, но OBS недоступен, проверь пароль WebSocket, порт и SSH-туннель.
